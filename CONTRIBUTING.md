# Contributing

Discuss substantial changes in an issue before opening a pull request. Keep
changes focused, describe the intended behavior and include regression tests.
Preserve other contributors' work and attribute actual authorship accurately.

Run the explicit public test list and check command in README. Never test
destructive, privileged, network-disrupting or hardware-changing operations on
a contributor's primary workstation. Use disposable fixtures or approved test
machines. Do not remove runtime publication guards as a shortcut.

Do not submit telemetry, personal profiles, exports, screenshots containing
identifiers, credentials, signing material, vendor executables or private logs.
Use synthetic fixtures. Review the entire staged diff, including metadata.

Keep missing, requested, pending, failed and verified-applied states distinct.
UI work must preserve keyboard access, readable text and narrow-window layouts.
Do not introduce high-frequency polling without measured justification.

Original contributions are submitted under the repository's MIT license.
Disclose third-party provenance and preserve all required notices. A public URL
or personal-use intent is not permission to copy code or assets.
